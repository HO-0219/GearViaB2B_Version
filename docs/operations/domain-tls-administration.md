# 도메인·SSL 관리 가이드

설치 후 접속 주소와 서버 인증서는 관리자 페이지에서 안전하게 시험하고 적용합니다. 설치기가
만든 초기 상태는 `https://<사설-IP>`와 로컬 CA가 발급한 자체 서명 인증서입니다.

## 구성 요소

- 백엔드는 승인된 공개 URL을 `deployment_settings` 단일 행에서 읽습니다. CORS, 동일 출처
  검사, WebSocket 허용 출처, 초대·비밀번호 재설정 링크가 모두 이 값을 사용하며 애플리케이션
  재시작 없이 반영됩니다.
- 백엔드 컨테이너에는 Docker 소켓이나 root 권한이 없습니다. 검증된 변경 요청만
  `/var/lib/gearvia/control/requests`에 기록합니다.
- root 소유 `gearvia-host-apply.path` / `.service` 유닛이 요청을 소비합니다. 요청 본문은
  설치 시 생성된 `HOST_APPLY_REQUEST_HMAC_KEY`로 HMAC-SHA256 서명되며, 적용기는 고정 경로와
  허용된 명령만 사용합니다.

## 변경 절차

1. 관리자 페이지 → **도메인·SSL**을 엽니다.
2. 새 공개 URL을 입력하고 인증서·개인 키 파일을 업로드합니다.
3. **연결 테스트**를 실행합니다. 인증서 형식, 만료일, SAN, 개인 키 일치를 검사합니다.
4. 테스트가 성공한 작업만 **적용**할 수 있습니다. 적용 직전 기존 공지 체계로 전체 사용자에게
   중단 알림이 발송되고, SMTP가 활성화되어 있으면 공지 메일도 발송됩니다.
5. 적용기가 후보 인증서를 원자적으로 교체하고 웹 컨테이너만 재생성한 뒤 HTTPS 상태를
   확인합니다. 실패하면 이전 인증서와 URL을 복원하고 작업이 `ROLLED_BACK`으로 전이합니다.

개인 키와 인증서 본문은 응답 DTO와 감사 로그에 포함되지 않습니다.

## 제거와 복구

기본 제거는 활성 `runtime.env`, `/etc/gearvia/tls`, `/etc/gearvia/host-apply.key`, 제어
디렉터리와 host-apply 유닛을 삭제하고 DB 볼륨·업로드·NAS 데이터와 DB 접속 복구 파일은
보존합니다. `--purge-data --confirm-purge GEARVIA`를 지정하면 복구 상태까지 삭제합니다.
외부 NAS의 파일은 절대 자동 삭제하지 않습니다.
